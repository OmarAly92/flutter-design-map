# flutter-map

Produce a visual map of a Flutter app's navigation: every route as a card with a screenshot, runtime state variants (bottom sheets, dialogs, modals), and navigation edges — packed into an expo-map-compatible `.appmap` bundle.

**Arguments:** optional path to the Flutter project (default: cwd). `--static` = parse + pack only (no simulator). `--prepare` = parse + write deep-link flow stubs / explore plan, stop before live capture.

**Working directory:** all outputs go to `<project>/.flutter-map/` — `graph.json`, `explore-plan.json`, `capture-status.json`, `screens/*.png`, `flows/*.yaml` + `flows/*.meta.json`, `*.appmap`. Suggest adding `.flutter-map/` to `.gitignore`.

**Parser / pack CLIs** live in this repo at `packages/flutter_map_parser`:

```bash
PARSER=<flutter-map-repo>/packages/flutter_map_parser
dart run $PARSER/bin/parse_routes.dart <project>
dart run $PARSER/bin/prepare_explore.dart <project>
dart run $PARSER/bin/pack_map.dart <project>
# or: dart run $PARSER/bin/flutter_map.dart <project>
```

## Flow recording (Phases 4–5)

Record interactions as **argent** flows: `<name>.yaml` + `<name>.meta.json` under `.flutter-map/flows/`. Replay: `npx @swmansion/argent flow run .flutter-map/flows/<name>.yaml`. Schema: `docs/appmap-format.md`.

Rules:
- Prefer argent MCP recording when connected; otherwise write YAML with normalized 0–1 coordinates.
- Sidecar `steps` keyed by 0-based YAML index. Navigating taps need `"screen": "<route id>"`. Screenshots are sidecar `capture` fields — never YAML steps.
- Mechanical deep-link flows are generated by `prepare_explore` — keep and update them after live captures.
- Never record credentials; use `{{secret:NAME}}` if input is unavoidable.
- Never tap destructive controls (delete, purchase, sign out, submit).

## Phase 1 — static parse

```bash
dart run $PARSER/bin/parse_routes.dart <project>
```

Report `graph.json` summary: mode (`go_router` / `go_router_builder` / `auto_route`), route count, edges (flag unresolved), state hints, params, scheme. If mode is unknown, stop.

If `--static`, jump to Phase 6 (pack with missing captures).

## Phase 2 — prepare explore plan

```bash
dart run $PARSER/bin/prepare_explore.dart <project>
```

This writes:
- `.flutter-map/explore-plan.json` — per-route deep links, sample params, `simctl`/`adb` commands, screenshot paths
- `.flutter-map/flows/deeplink-<slug>.yaml` + `.meta.json` — deterministic open-url flows
- `.flutter-map/capture-status.json` — all routes start as `missing`
- `.flutter-map/screens/` directory

Review sample params: prefer values from resolved edge targets (e.g. `/details/42`), then fixture/seed data, else `1`. Edit `explore-plan.json` if needed before sweeping.

If `--prepare`, stop here and report the plan.

## Phase 3 — boot the Flutter app

1. Prefer an already-running app on a booted simulator/emulator.
2. iOS: `xcrun simctl list devices booted`. Android: `adb devices`.
3. Run the app (`flutter run -d <device>` or attach to an existing debug session). Note the bundle id / application id.
4. **Verify deep linking** using the scheme from `graph.json` / `explore-plan.json`:
   - iOS: `xcrun simctl openurl booted "<scheme>://"`
   - Android: `adb shell am start -a android.intent.action.VIEW -d "<scheme>://"`
5. Confirm the app rendered (screenshot). If deep links fail, fix Android intent-filters / iOS URL types, or continue with in-app navigation only and mark `needsNavigation` later.

## Phase 4 — route sweep

For each route in `explore-plan.json`:

1. Open `deepLink` (or the platform command in the plan).
2. Wait ~1.5s (3–4s for network-heavy screens).
3. Capture using the exact `slug`:
   - iOS: `xcrun simctl io booted screenshot <project>/.flutter-map/screens/<slug>.png`
   - Android: `adb exec-out screencap -p > <project>/.flutter-map/screens/<slug>.png`
4. Update the matching `flows/deeplink-<slug>.meta.json` `device` field once known.
5. Sanity-check periodically. Keep bad captures but note them for Phase 4b.

### Phase 4b — review and recover

Write verdicts to `.flutter-map/capture-status.json`:

```json
{ "<routeId>": { "status": "ok", "needsNavigation": false, "note": null } }
```

Statuses: `ok` · `empty-state` · `not-found` · `error-boundary` · `loading` · `auth-wall` · `missing`.

Flutter-specific notes:
- Red error screens / yellow-black stripes → `error-boundary`; relaunch the app before continuing (`flutter` hot restart, or terminate + relaunch) — error UI can poison later captures.
- GoRouter redirects (auth) → capture what rendered; set `auth-wall` or note the redirect target.
- Routes that only work via typed `context.router.push` / shell tabs may need `needsNavigation: true` if bare deep links land on the wrong stack.

## Phase 5 — runtime states

For each route with non-empty `stateHints`:

- **bottom-sheet** — find the trigger in `file`, tap it, capture `screens/<slug>--sheet.png` (or `--sheet-<snap>` if snap points exist).
- **dialog** — trigger, capture `screens/<slug>--dialog.png`, dismiss.
- **modal** / **router-modal** — capture variant or treat as own route if already in the graph.

Coverage line required: `state hints: N · captured M · skipped K (why)`.

### Phase 5b — navigation flows

For reachable routes, record `flows/nav-<slug>.yaml` + sidecar (human tap path from app root). Deep-link stubs alone are not enough for pinnable edges.

## Phase 6 — pack and deliver

```bash
# optional downscale on macOS
for f in <project>/.flutter-map/screens/*.png; do sips -Z 800 "$f" >/dev/null; done

dart run $PARSER/bin/pack_map.dart <project>
```

Deliver the `.appmap` zip. Open in the expo-map visualiser (drag-drop). Report: routes captured / total, state variants, skips, unresolved edges. Suggest gitignoring `.flutter-map/`.

## Replay

```bash
npx @swmansion/argent flow run <project>/.flutter-map/flows/<flow-name>.yaml
```

Fallback: execute YAML steps via `simctl`/`adb` + simulator MCP using sidecar `target` labels.
